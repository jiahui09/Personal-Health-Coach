# Personal Health Coach · Living Journal

一个安静、单页的**个人健康手记**：你如实记录事实，它替你算账并告诉你下一步——下一餐吃什么、下一次怎么动、身体正在如何变化。

**不接大模型**。所有建议都由确定性的 TypeScript 纯函数计算（LLM = OFF）：同样的输入永远得到同样的输出，每条建议都标注依据、假设与局限，可复现、可追溯，没有生成式幻觉，也不调用任何外部 AI 接口。

## 它做什么

页面是一条单页流：**刊头 → 今日之事 ↔ 今日之练 → 体征 → 营养摄入 ↔ 统计**。窄屏自动改纵向单列，右下角有悬浮章节目录，点章名即到该栏。

| 区块 | 做什么 |
| --- | --- |
| **刊头与序** | 时段问候（朝安 / 昼安 / 夜安）与干支日期 |
| **今日之事** | 今日待办增删勾选，拟时长随手可改 |
| **今日之练** | 依睡眠、精力、酸痛判定训练状态（REST / RECOVERY / LIGHT / NORMAL）；课表按肌群账本与时间预算搭配，动作、组数、次数可就地改 |
| **体征** | 只收原始事实：今之体重与腰围、档案所录、由就寝/起身时刻推得的夜眠、精力与酸痛圆点 |
| **营养摄入** | 依体征与目标算出今日热量 / 蛋白 / 脂肪 / 碳水，逐条显示「尚余 / 已超」，下一膳推荐点「照准」即入账 |
| **统计** | 体重指数、静息代谢与总消耗、每周抗阻处方、近七日均重与三十日趋势、四周 / 八周 / 十二周情景外推 |

录事共三张表（**录一膳 / 录一练 / 录体征**），入口分就地打开；进食表内嵌食物营养档案，搜名即现、点选自动回填克数。全页只有一张图表（30 日体重折线），其余数字写进手记行文——没有 KPI 卡片，没有环形进度。

### 建议分级（方法论）

每条规则强制标注三级之一，在页面上如实呈现：

| 分级 | 含义 | 例子 |
| --- | --- | --- |
| `evidence_derived` | 文献中的直接公式 | Mifflin-St Jeor 静息代谢预测 |
| `evidence_constrained` | 指南与综述给出的约束区间 | 蛋白质 1.4–2.0 g/kg、睡眠 ≥7 小时 |
| `engineering_heuristic` | 工程启发式，不伪装成医学结论 | 精力/酸痛判定训练状态、餐食排序 |

配套的证据登记表只收录可核实的来源（Mifflin 1990、Morton 2018、WHO 2020、AASM/SRS 2015 等 10 条），每条写明结论与局限。

### 术语与口径

页面只写事实，解释性口径集中在这里；完整定义见 `docs/data-semantics.md`。

- **待核（needs_review）**：只标记，绝不改数；被标记的记录原样保留，可逐条「掷还」。
- **尚余 / 已超**：由同一函数给出（余 = 目标 − 已录、超 = 已录 − 目标），不会用「尚余 0」掩盖超额。
- **拟 / 估算 / 实际**：计划时长标「拟」、产品估算标「约」，只有用户计时才标「实际」，三者互不冒充。
- **端点变化 ≠ 回归斜率**：三十日变化取首末有效日，回归斜率另算，页面分列两行。
- **睡眠只有一个来源**：填了就寝/起身则由时刻推得时长；近七日均只按有记录的夜数平均，缺就如实写明。
- **情景外推**：由近三十日斜率乘周数再折减得出的区间，标注依据日数；数据存疑即不出数——它是情景，不是承诺。

## 快速开始

```bash
npm install
npm run dev        # http://localhost:3000
```

```bash
npm run lint       # 类型检查（tsc --noEmit）
npm test           # 契约与审计测试
npm run build      # 生产构建
```

环境变量见 `.env.example`，只有两项：`VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`。**两项都留空即本地模式**，数据保存在浏览器 localStorage，零配置即可运行。

## 数据存哪里

- **本地模式（默认）**：数据只在本机浏览器；页脚「复其初」一键恢复演示数据。
- **云端同步模式**：填上两项环境变量后改走 Supabase——页内邮箱密码注册/登录，登录时**询问后**再把本机记录并入账号，切回页面自动重取；6 张表全部启用行级安全（RLS），每行数据只能被本人读写。
- 部署到 Cloudflare Pages 的逐步操作见 `docs/deploy.md`，建表脚本见 `supabase/schema.sql`；上线前可运行 `node scripts/verify-supabase.mjs` 自检。

## 技术栈与结构

React 19 · TypeScript · Vite · Tailwind CSS v4 · motion（动效）· lucide-react（图标）。连 Supabase 用原生 `fetch` 直连（PostgREST + GoTrue），零新增依赖。

```
src/
├── App.tsx          # 单页编排：状态、弹窗、区块组合
├── components/      # 展示组件（各节、录事三表、共用表壳、悬浮目录）
├── services/        # 数据访问：repository 工厂 + 本地/云端两实现 + 组装层
├── domain/          # 纯函数规则：代谢、趋势、营养、训练、阈值
├── data/            # 演示数据、食物档案库、章节目录
├── types/           # 全部领域模型（单一类型来源）
└── tests/           # 契约与审计测试
```

分层：`UI → HealthRepository（接口）→ 工厂 → 本地 / 云端实现`，换数据源只改工厂一处，页面无感。

**质量门禁**：`npm run lint` · `npm test` · `npm run build`。文字对比度、触控目标、版式与展示口径均由测试锁定。构建产物约 552 KB JS（gzip 约 174 KB）。
